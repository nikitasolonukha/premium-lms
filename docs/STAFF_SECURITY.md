# Административные сессии и журнал

Staff-сессия привязана к настоящему `auth.sessions.id`: абсолютный срок 12 часов, простой 30 минут. Refresh JWT не создаёт новую административную сессию. Обычный просмотр или изменение административной страницы считается активностью; фоновая проверка `GET /api/staff-session`, prefetch маршрутов и обновление playback grant — нет.

Next.js скрывает Flight-заголовки и в Proxy, и в `headers()`. Включён официальный `skipProxyUrlNormalize`, чтобы Proxy увидел исходные транспортные признаки: `next-router-prefetch`, `next-router-segment-prefetch`, `purpose` и `sec-purpose`. Proxy всегда перезаписывает `x-lms-background-prefetch`, игнорируя входное значение клиента. Сервер выбирает readonly `staff_session_status` для фонового запроса; обе RPC независимо проверяют живой настоящий session ID, роль из БД, MFA, подтверждение email и оба срока. Подмена транспортного признака не обходится без этих проверок. [Next.js: RSC requests and rewrites](https://nextjs.org/docs/app/api-reference/file-conventions/proxy#rsc-requests-and-rewrites).

Предупреждение появляется за две минуты до ближайшего срока. «Продолжить сессию» — явная same-origin Server Action с проверкой MFA/роли/живой сессии и ограничением частоты. Она продлевает только ещё действующий idle deadline; абсолютный срок остаётся прежним. Истёкшая сессия требует повторного входа. Открытый редактор не перенаправляется автоматически, чтобы не терять несохранённый текст. При недоступной сети показывается ошибка проверки; сервер продолжает независимо применять ограничения.

Журнал Admin фильтруется по действию, имени/email/ID автора, типу/ID объекта и включительным датам по Москве. RPC ограничивает выдачу 30 записями и частоту поиска. Аналитика возвращает 20 курсов на страницу, общие показатели рассчитываются по всей академии.

Конфигурация Cloudflare/Mux задаётся окружением deployment, поэтому у такого изменения нет web-пользователя. Readiness, настройки и выдача защищённого playback проверяют запись наблюдения: `video.provider_config`, actor=NULL, environment и два enabled-флага. В закрытой `private.video_config_state` хранится HMAC fingerprint конфигурации; значения ключей, fingerprint и signing URL в audit metadata не попадают. Наблюдение идемпотентно для неизменной конфигурации и повторяется после сбоя БД. Readiness не возвращает OK до успешной записи. При rolling deployment два процесса могут последовательно наблюдать разные конфигурации; для установления оператора используйте журнал deployment. Ротация RATE_LIMIT_SECRET также создаёт новое наблюдение.
