# Ученики, отчёты, автоматизации и собственные видео

Оплата в этот модуль не входит. Учебные материалы и пользовательские доступы остаются в существующих редакциях/RLS.

## Пользователи

Admin открывает имя в `/admin/users` и получает `/admin/users/<uuid>`: email, роль, состояние аккаунта, дату регистрации/входа, доступные и ранее назначенные курсы, прогресс по опубликованной программе, последний урок и последние 50 событий. Курсы имеют серверную пагинацию по 20. Отзыв ручного назначения сохраняет прогресс; курс для всех зарегистрированных остаётся доступным.

В «Массовых действиях» выбираются активные Student текущей страницы. Выбор курса поддерживает поиск/пагинацию. Назначение и отзыв требуют подтверждения. Операция транзакционная; UUID запроса и fingerprint защищают повтор, enrollment/grant не дублируются. Ошибочный пользователь откатывает всю группу.

Импорт: CSV UTF-8 с BOM/без BOM, `,`/`;`, либо XLSX с одним листом, до 500 учеников, 20 колонок и 1,5 МБ. Колонки `email`, `first_name`, `last_name` (или «почта», «имя», «фамилия»). Скачиваемый шаблон встроен в интерфейс. XLSX проходит ZIP/CRC/expansion/active-content проверки; формулы и объекты в ячейках запрещены. Персональные данные не выгружаются в логи.

Предпросмотр хранится сервером и привязан к владельцу. Повтор email, неправильные поля, аккаунт сотрудника или отключённый ученик блокируют подтверждение. Новые аккаунты получают приглашение Supabase Auth с ролью Student и ссылкой установки пароля; существующие имена/роли/пароли не перезаписываются. Необязательное назначение курса выполняется после повторной проверки роли ученика. Каждая обработанная строка записывается отдельно. При сбое SMTP/Auth повтор пропускает выполненные строки; возможный исход приглашения проверяется по email перед повтором. Окончательный результат виден в `/admin/automations`.

## Фоновый обработчик

Миграции `20260930172019`, `20260930174513`, `20260930180110`, `20260930182602` создают закрытую очередь и проверяемые операции. `npm run worker` запускается отдельно от `npm start`. Нужны серверные env Supabase и Node 22.19+ с type stripping. Работает одна задача на процесс; можно несколько worker, но Telegram long polling запускается только в одном. Claim использует `FOR UPDATE SKIP LOCKED`, UUID lease, heartbeat 15 секунд. Админка проверяет heartbeat, обновляет статусы каждые 10 секунд только во видимой вкладке.

Зависший import/video после 5 минут повторяется до трёх захватов; затем нужна ручная попытка. Для отчёта зависание даёт `DELIVERY_UNKNOWN`, без автоматической повторной отправки. Подтверждённые доставки сохраняются по получателям. Если Telegram принял сообщение, но подтверждение или запись результата потерялись, ручной повтор может отправить его ещё раз: интерфейс явно предупреждает.

Перед выполнением и записью результатов БД заново проверяет действующую роль автора, подтверждение email, verified TOTP и отключение аккаунта. Фоновая делегация не требует открытой браузерной сессии: расписание и связанный личный Telegram должны работать после выхода владельца. Интерактивное создание/изменение требует настоящего Admin/AAL2/live session; видео доступно также Editor. Понижение/отключение/удаление MFA владельца отменяет задание.

## Telegram

1. Создать бота через [BotFather](https://t.me/BotFather).
2. Сохранить токен в серверный `TELEGRAM_BOT_TOKEN`, перезапустить сайт и worker. Токен нельзя помещать в `NEXT_PUBLIC_*`, репозиторий или отправлять ученикам.
3. В `/admin/automations` нажать «Подключить мой Telegram», открыть одноразовую ссылку и Start в личном чате. Ссылка действует 5 минут, в БД хранится hash. Имя бота получает worker через `getMe`.
4. Команды: `/summary`, `/courses` (кнопки отчётов по конкретному курсу), `/students`, `/inactive`, `/completions`, `/help`. Отчёты с персональными данными доступны только связанным действующим Admin в личном чате. Группы, чужие chat ID, неизвестные команды и повтор update ID отклоняются. Лимит 20 команд в минуту на связь.
5. «Отключить мой Telegram» отзывает связь. Для смены аккаунта создать новую ссылку из админки.

По умолчанию `TELEGRAM_MODE=poll`; публичный endpoint не нужен. Webhook: `TELEGRAM_MODE=webhook`, отдельный CSPRNG `TELEGRAM_WEBHOOK_SECRET`, зарегистрировать у Telegram HTTPS `/api/telegram` с таким же `secret_token`. Заголовок сравнивается безопасно, тело ограничено 16 КБ. Webhook и getUpdates одновременно не используются. Реальная доставка без токена считается UNVERIFIED, а не PASS.

## Правила

В `/admin/automations` задаются имя, тип отчёта, ежедневное/недельное расписание, время, день недели, IANA timezone и связанные получатели. Включение/пауза, редактирование, запуск сейчас и подтверждённый повтор ошибки доступны в интерфейсе. Расписание рассчитывает PostgreSQL с учётом часового пояса; уникальный ключ rule/time предотвращает двойную постановку. После простоя отправляется одна актуальная сводка, пропущенные интервалы не рассылаются пачкой.

Сводка — новые пользователи/активность/завершённые уроки за сутки; неактивные — назначенные ученики без активности 7 дней (до 500); завершения текущих программ за неделю (до 500); список курсов (до 50); CSV прогресса (до 5000 строк). CSV содержит BOM, экранированные ячейки и защиту от формул. Это отчёт текущих назначений/программы, не финансовый отчёт или произвольный SQL. Списки заданий ограничены 100, видео — 50; большие регулярные выгрузки требуют отдельного расширения пагинации.

## Видео с вшитым названием

В `/admin/videos` Admin/Editor выбирает MP4 до 1 ГБ, надпись до 120 символов и разрешение скачивания (по умолчанию выключено). Название берётся из текущего бренда, можно изменить перед загрузкой. Оно фиксируется в задании; изменение бренда не меняет готовые файлы. Исходник хранится в отдельном закрытом bucket `academy-video-source`, недоступном ученикам и обычным Storage API сотрудника.

Worker проверяет реальный размер, MP4 `ftyp`, ffprobe, видеопоток, длительность до 4 часов и размеры до 4096×4096. FFmpeg без shell и внешних протоколов, с выключенными external data references, перекодирует H.264/AAC, до 1920×1080 без растягивания, faststart, удаляет метаданные. Надпись читается из текстового файла, expansion выключен; filename/title не вставляются в команды или filter grammar. Ограничения: 2 потока кодирования, 3 часа на обработку, выход до 2 ГБ. Готовятся WebP-обложка и варианты 480/960/1800. Состояние `ready` выставляется транзакцией только после загрузки всей версии и обложек. Исходник после успеха удаляется; при ошибке остаётся для повторной обработки. Незавершённую загрузку следует повторить с файлом; pending-объекты нужно включить в периодическую эксплуатационную очистку.

В блоке «Видео» выбрать «Загруженное видео · с надписью», готовый файл и сохранить. Admin публикует редакцию. Блок связывает media с редакцией через `block_assets`; студент получает только готовый MP4 после проверки сессии, публикации, enrollment и последовательности уроков. Ссылка просмотра до 5 минут, автоматически обновляется с сохранением позиции. Новые ссылки после отзыва не выдаются. Старый signed URL живёт до TTL. Скачивание, если включено при загрузке, выдаётся на 60 секунд и содержит **вшитую надпись**; оба маршрута проверяют флаг скачивания.

Длинное название автоматически переносится по ширине кадра; размер и отступы учитывают соотношение сторон. Название остаётся на кадре в fullscreen, скриншоте и копии файла. Это не DRM: нельзя обещать запрет записи экрана, кадрирования или удаления надписи монтажом. Персональный движущийся watermark остаётся отдельной настройкой плеера; этот модуль вшивает название проекта в общую готовую версию.

## Развёртывание worker

Linux использует системные `ffmpeg`/`ffprobe` с фильтром `drawtext` и DejaVu Sans; на Debian/Ubuntu установить `ffmpeg fonts-dejavu-core` либо запускать готовый Docker worker. Закреплённый `ffmpeg-static` Linux не содержит drawtext и для вшивания не подходит. Windows использует проверенный static binary и Arial, либо заданные `FFMPEG_PATH`/`FFPROBE_PATH`/`FFMPEG_FONT_PATH`. На другой ОС явно настроить доступный кириллический font. При старте проверяются drawtext и файл шрифта; неподготовленный обработчик не объявляет видео готовым к обработке.

Для видео до 1 ГБ и результатов до 2 ГБ глобальный Storage upload limit должен быть не ниже 2 ГБ; лимит bucket не может превысить глобальный. Локальный config выставлен в 2 GiB, обычные документы по-прежнему ограничены приложением/БД 50 MiB. В hosted Supabase проверить доступные лимиты выбранного тарифа и включить нужный global limit в Dashboard. [Официальные ограничения](https://supabase.com/docs/guides/storage/uploads/file-limits). Для исходников близко к 1 ГБ рекомендуется отдельное расширение resumable upload; текущая загрузка обычная, с прогрессом и ручным повтором после обрыва.

`docker build -f Dockerfile.worker -t academy-worker .`

Запускать отдельным сервисом с серверным env-file, рестартом, лимитом CPU/RAM, закрытой сетью, достаточным временным диском (не менее исходника + результата + резерв). Образ содержит системные FFmpeg и DejaVu Sans с кириллицей, выполняется от `node`. Не помещать обработку в короткоживущий serverless веб-запрос. Проверить использование H.264/AAC/FFmpeg лицензий для выбранной поставки. Секреты не входят в образ. В production применять проверенные image pin/digest, мониторинг heartbeat и квоты Storage/диска. Сам Docker worker image на production-хосте ещё требует проверки.

Очередь/правила/связи сохраняются в private-схеме и должны входить в резервную копию БД; original и processed bucket — в копию Storage. Старые previews, непривязанные pending-видео, bot update IDs, задания и данные импорта следует удалять согласно политике хранения персональных данных. Не удалять используемые media через обход обычной защиты.

## QA

`npm run test:academy` выполняется на существующем локальном Supabase **без reset** с изолированными QA-записями; перед ним остановить только свой worker. Затем запустить `npm run worker` и `npx playwright test tests/e2e/academy-operations.spec.ts` на production-сборке. Интеграционный QA не перезаписывает существующую Telegram-связь. Реальные токен/SMTP/deployment проверяются отдельно.
